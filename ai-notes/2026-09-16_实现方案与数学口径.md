# 实现方案与数学口径

## 关键决策

- 用户要求独立本地网页计算器，采用零依赖静态前端与 Node 本地服务。比较过独立工具与并入现有回本工具，选择独立工具以满足本次范围。
- 视觉沿用相邻 LP 回本工具的浅色工作台语汇：冷灰底、白色表单、蓝色交互、中文系统字体，强调计算本身。
- 四项输入是现有本金、当前活跃份额、当前整体手续费 APR、追加金额。只有本金与份额不足以求年化。

## 模型

K 为原本金，s 为原 active 小数，a 为追加金额，r 为原整体手续费 APR 小数。令 d = K / (K + s × a)。

- 追加后整体 APR = r × d。
- 本次整笔追加 APR = r × (1 − s) × d。
- 新增年手续费 = a × 本次整笔追加 APR。
- 追加后的下一小笔 APR = r × (1 − s) × d²。
- 追加后份额 = s + (1 − s) × (s × a / (K + s × a))。

不要用 1 − 追加后份额反算边际收益，接近 100% 时会有浮点消去误差。a=0 时整笔追加 APR 未定义，显示尚未追加；下一小笔 APR 仍可展示。s=100% 时固定手续费模型下所有追加增量为零。

## 验证计划

用 Node 内置测试覆盖基准、守恒、比例缩放、边界和错误输入，再运行静态打包与浏览器桌面/手机交互验证。默认模型追加 1000 U 应为 13.3333% APR，追加后份额 77.7778%，新增年手续费 133.3333 U。

## 当前状态

已实现独立零依赖工具。入口 `npm run dev`，默认本机地址 `http://127.0.0.1:5193/`；`npm run build` 打包，`npm start` 服务打包产物。原仓位、追加输入都在本机运算，不上传、不持久化。

## 验证证据

- Node 内置测试 9 项通过：基准、收入守恒、资金规模缩放、边际单调性、零追加、100% 份额、零手续费与高 APR、极小份额/大金额、无效输入。
- `npm run check` 语法检查、`npm run build` 打包通过。
- Playwright 验证默认结果、0 追加、高年化、100% 份额、空值、101% 份额、小额追加、滑块和键盘联动、账本。
- 1440、768、390、320px 无页面横向溢出，手机 200% 字号无横向溢出，无脚本错误和外部请求。
- 手机新增 sticky 年化摘要，首屏可见；无效参数显示待计算，0 追加显示尚未追加，焦点输入未被遮挡。

- Impeccable 检测器缺少 HTML 解析依赖，仅降级正则检查，不能视为完整静态审计。独立审查按 CSS 色值核验正文对比度，浏览器执行验证如上。
- 可选 WebMCP 原生环境不可用；用注入接口验证注册、参数更新、无效输入拒绝与状态保持，未宣称原生集成验证通过。

## 数值边界

对现实计算范围设置显式上限与错误提示：本金 0.000001~1e12 U，追加 0~1e12 U，份额 0.00000001%~100%，APR 0%~1,000,000%。未使用任意浮点极值的对数计算，避免不必要的复杂性。
